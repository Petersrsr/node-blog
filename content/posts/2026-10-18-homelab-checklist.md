自己那套环境跑了挺久，出过几次「莫名其妙重启后某个盘没了」的问题之后，我固定了一套巡检顺序。

## 硬件底子

| 部件 | 型号 | 备注 |
|------|------|------|
| 宿主机 | 2× E5-2698B v3 | 16C32T，双路 |
| 内存 | 64 GB | DDR4 ECC |
| 系统盘 | 256 GB SSD | PVE 本身 |
| 存储 | 2× 4TB IronWolf | RAID1，直通给 NAS |
| 虚拟化 | Proxmox VE | KVM + 容器 |

## 巡检顺序

1. **看存储是否在线** —— 直通盘在宿主机重启后偶尔不出现。
2. **看网络** —— 内网几个关键地址能不能 ping 通。
3. **看服务** —— 各个自启单元状态。
4. **看容量** —— 数据盘和系统盘的剩余空间。
5. **看日志** —— `journalctl -p err --since today` 扫一遍红字。

```bash
# 一键过一遍
pvesm status
ip -br a
systemctl list-units --failed
df -hT
journalctl -p err --since today | tail -50
```

## 两个反复踩的坑

> 直通给虚拟机的磁盘，宿主机重启后如果目标虚拟机先于存储栈起来，虚拟机会拿不到盘，之后也不会自动重连 —— 表现就是「NAS 里少了一块盘」。

**解决办法**：给虚拟机加启动延迟，或者把存储相关的依赖显式挂到虚拟机自启顺序后面。

> USB 硬盘盒走 UAS 时偶发掉盘。表现是 `dmesg` 里刷 `uas_eh_device_reset_handler`，之后整块盘消失。

**解决办法**：内核启动参数里对该设备禁用 UAS，让它退回 usb-storage。

```bash
# 查设备 ID
lsusb
# 内核参数加（示例）
usb-storage.quirks=152d:0578:u
```

## 一条原则

改动之前先想清楚「回滚路径是什么」。家庭环境没有第二个运维，半夜出问题只能靠自己，而人在这个状态下最容易做错判断 —— 所以能白天做的变更，绝不留到晚上。

相关：`pvesm status` 输出里如果某一项是 `inactive`，别急着重启宿主机，先看是不是多路径或 SMART 报警。
